{# Base layout (Task 06) with the T16a shell: sidebar (--sidebar-w) · page · context panel (--context-w). Everything is served from local static files: no CDNs and no external requests — the diary page never talks to the internet (docs/privacy-and-safety.md §3). Jinja2 autoescape is on for .html files. The layout, the token names and the breakpoints follow the UI reference mockup kept at ``docs/mockups/mydiary-ui-mockup.html`` (task T16a); that file is the artefact the acceptance compares against. Navigation carries no dead entries: every link below points at a route that exists. Mockup items without a page yet ("Хронология", "Настройки") are not rendered at all, the counters come from the database (the ``nav`` context computed in ``api/routes/pages.py``) and the mockup's search button is omitted because there is no search endpoint. ``nav_current`` (a plain string) picks the highlighted item and is passed by every page — including the database-free privacy page, which passes no ``nav`` and therefore shows no counters. The list itself lives in ``_nav_links.html`` because it is rendered twice (task T16b): once in the sidebar and once in the compact topbar menu that keeps the sections reachable under 700px, where the sidebar is hidden. The compact menu is a native ``

The context panel is rendered only when a page sets ``context_panel = true`` *and* fills the ``context`` block (Jinja cannot tell "empty block" from "block not overridden" without rendering it twice, so the page declares its intent). Today exactly one page does — the day page, whose processing panel is task T16c — so the shell stays two-column everywhere else instead of reserving an empty 332px column.
