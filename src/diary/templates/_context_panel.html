and only when ``context_panel`` is set, so no other page reserves the column. The mockup ties its panel to one record. A day holds several records and the derivational layers do not share an anchor (ADR-007 §1, ADR-008), so this panel is a *day* panel of two honest blocks instead: 1. «Записи дня» — the requested local day: how many entries, how many have audio, how many are transcribed and how many are still waiting. Each voice record gets a row with its real transcription state (the caption and the button label come from the same batch loader the card below is rendered with) and — when transcription can be started *and* that card is on this page — a link to that card's own "Расшифровать" button. The panel adds no second trigger: the STT action and its job poller exist once, in ``static/js/app.js``. A day longer than the feed's page window keeps such rows too — the day block counts the whole day — but marks them ("в более старых записях") instead of linking to a card that is not rendered yet. 2. «Недельные слои» — the weekly export of the week this day belongs to: normalization, summary and wellbeing are stored per *export*, not per message, so they are shown here with links to the existing export pages. A week without an export says so and links to ``/exports``, where one is created. 3. «Слои фазы 2» (task T37) — the second-family results anchored to this very day and to its ISO week (``daily_summary`` and ``weekly_summary``), with the mockup's «Показать происхождение» control, which opens the chain «артефакт → источник → прогон обработки» on the artifact's own page. The control is rendered only for an artifact that exists; a layer without a result says «Не посчитано» and offers nothing (a dead control is worse than none). The other two second-family layers are anchored to a single message and to a weekly-summary artifact, i.e. to something this page is not, so they are not listed here. What is deliberately absent (dead elements are worse than missing ones): the mockup's "Экспортировать запись" (the product exports weeks, not single entries) and its close button (the panel is server-rendered; closing it would only hide information, not navigate anywhere). No diary text is rendered here — only counts, statuses, times, file names and model names read from the configuration. No script of its own: the panel is a snapshot of the server state, and it says so. #}
