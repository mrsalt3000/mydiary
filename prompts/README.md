# prompts/ — политика промптов

Каталог содержит версионируемые промпты конвейеров. Подкаталоги: `normalize/`, `summarize/`, `wellbeing/` (файлы вида `v1.md`, `v2.md` создаются в задачах Task 13–15).

## Правила

- **Версионирование:** промпт — файл `v<N>.md`; изменения — новый файл `v<N+1>.md`, старый не перезаписывается. Номер версии промпта фиксируется в метаданных прогона (`processing_runs`) и обеспечивает воспроизводимость и трассируемость.
- **Содержимое:** промпты содержат инструкции и синтетические примеры. **Запрещено** включать содержимое дневника пользователя (реальные тексты, транскрипции, выдержки из записей).
- **Структурированный вывод:** каждый промпт требует строгий JSON-вывод, описываемый Pydantic-схемой соответствующего конвейера (Task 12–15); вывод валидируется до записи артефакта.
- **Ограничения предметной области** вшиваются в текст промпта: нормализация не добавляет/не удаляет факты; саммари не вводит новых фактов; wellbeing не диагностирует (см. также `../skills/llm-pipelines/SKILL.md`, `../skills/wellbeing-safety/SKILL.md`).
- Промпты не содержат секретов и персональных данных; в логи текст промптов с содержимым дневника не попадает.

См. также: `../docs/architecture-brief.md` §10; `../docs/data-lineage.md`.
