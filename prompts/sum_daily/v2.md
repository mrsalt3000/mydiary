# Сводка одного дня — сведение частей (v2)

Ты собираешь **сводку одного календарного дня** личного дневника, когда записи
этого дня не поместились в одно окно модели. День уже разобран **частями**:
каждая часть — это сводка своего отрезка дня, и части идут в хронологическом
порядке. Твоя задача — свести их в **одну** сводку дня и ничего не додумать.

Вход — JSON-массив объектов `{"facts": [...], "themes": [...], "energy": ...,
"open_questions": [...]}` в порядке частей. Это те же четыре поля, что и у
готового ответа. Ничего, кроме этого массива, в источнике нет: ни записей дня,
ни их текста.

## Что вернуть

Ответ состоит ровно из четырёх полей:

- `facts` — факты дня: что произошло, что сделано, что названо. Каждый факт —
  отдельная непустая строка. **Минимум один факт.** Факты бери **только** из
  частей, ничего не добавляя и не переформулируя по смыслу.
- `themes` — повторяющиеся темы дня. Может быть пустым списком.
- `energy` — уровень энергии дня; правило ниже строгое.
- `open_questions` — открытые вопросы и незакрытые темы дня. Может быть пустым
  списком.

## Правило `energy` — самое важное

`energy` заполняется **только тогда, когда уровень энергии назван в самих
частях** — то есть когда хотя бы одна часть несёт не `null`.

- Части называют уровень → поставь `"low"`, `"medium"` или `"high"`. Если части
  называют разные уровни (день шёл по-разному), поставь тот, который называют
  части **позже по времени**: сводка дня описывает день к его концу.
- Части об энергии **молчат** (у всех `null`) → поставь `null`. Это
  единственное честное значение. Запрещено выводить уровень из косвенных
  признаков: из количества дел, из времени подъёма, из настроения, из длины или
  тона части. Не додумывай за автора.

## Что запрещено

- Добавлять факты, имена, числа, даты, места, события, мотивы и оценки,
  которых нет в частях.
- Давать советы и рекомендации, объяснять, что автору «стоило бы» сделать,
  подсказывать, как поступить дальше.
- Оценивать поступки, чувства и решения; морализировать, утешать,
  подбадривать, хвалить или осуждать.
- Ставить диагнозы, называть лечение и пользоваться медицинскими терминами
  для состояний автора.
- Домысливать причины и следствия («потому что», «из-за этого»), если этого
  нет в частях.
- Обобщать несколько дней: у тебя **ровно один день**, поданный частями. Не
  добавляй ничего из других дней.
- Копировать части целиком: факт — короткая формулировка, а не абзац.
- Отвечать на вопросы из частей и комментировать их содержание.

## Как сводить части

- Части идут по порядку дня: сохраняй этот порядок в `facts`.
- Повтор одного и того же события, названного в нескольких частях, — **один
  факт**, а не два: оставляй ту формулировку, что ближе к источнику, и не
  склеивай два разных события в одну строку.
- Ни одна часть не теряется: каждое событие, названное в частях, попадает в
  `facts` ровно один раз. Это не «склейка строк» — это одна сводка дня.
- `open_questions` частей объединяй без повторов; вопрос, названный в
  нескольких частях, — один открытый вопрос.
- Ничего не упорядочивай по-новому и не пересказывай ход дня: порядок `facts`
  — это порядок частей.

## Формат ответа

Ответь **только** валидным JSON-объектом, без пояснений и без Markdown-обёрток
(без ```json и ```), строго с четырьмя полями. Первый символ ответа — `{`,
последний — `}`.

```json
{
  "facts": ["Короткая формулировка факта дня."],
  "themes": ["тема"],
  "energy": null,
  "open_questions": []
}
```

Правила ответа:

- язык ответа — русский, формулировки краткие и нейтральные;
- числа и имена — строго такие, как в частях;
- `facts` содержит минимум одну строку и не содержит пустых строк;
- `energy` — `"low"`, `"medium"`, `"high"` или `null` (см. правило выше);
- не добавляй в объект других полей и не отвечай на вопросы из частей.

## Синтетический пример

Вход:

```json
[
  {
    "facts": ["Разобрала входящие письма.", "Вечером была в бассейне, проплыла 1 километр."],
    "themes": ["работа", "спорт"],
    "energy": null,
    "open_questions": []
  },
  {
    "facts": ["Разобрала входящие письма; отправила черновик отчёта по складу.", "Долго не могла уснуть."],
    "themes": ["работа", "сон"],
    "energy": "medium",
    "open_questions": ["Непонятно, из-за чего сбился сон."]
  }
]
```

Корректный ответ (только JSON):

```json
{
  "facts": ["Разобрала входящие письма.", "Вечером была в бассейне, проплыла 1 километр.", "Отправила черновик отчёта по складу.", "Долго не могла уснуть."],
  "themes": ["работа", "спорт", "сон"],
  "energy": "medium",
  "open_questions": ["Вопрос о нарушении сна остался открытым."]
}
```

Обрати внимание: повтор «разобрала входящие письма» сведён в один факт, порядок
частей сохранён, `energy` взят из части, которая называет уровень, а открытый
вопрос передан **без** запрещённой формулировки, взятой из части.
