# ADR-001: SQLite — локальный источник истины для метаданных и состояния

- Status: Accepted
- Date: 2026-09-09

## Context

Личный однопользовательский дневник работает локально в WSL 2. Системе нужен единый источник истины для сообщений, метаданных аудио, транскрипций, выгрузок, прогонов обработки и состояния фоновых задач, при этом без внешних сервисов и без операционных затрат. Рассматривались альтернативы: PostgreSQL, файлы-«как есть» без БД, внешние брокеры задач.

## Decision

SQLite является источником истины для постоянных метаданных и состояния: таблицы `messages`, `audio_files`, `transcriptions`, `weekly_exports`, `processing_runs`, `artifacts`, `jobs` (Task 04). Доступ — через SQLAlchemy 2 и репозитории; изменения схемы — только через Alembic-миграции. Файлы аудио/артефактов при этом остаются на локальной ФС (ADR-002), а в БД хранятся их метаданные и безопасные пути.

## Consequences

Положительные:

- Ноль внешних зависимостей для хранения; простое резервирование (копия файла БД); транзакционность для согласованности метаданных и состояния задач; достаточная надёжность для одного локального пользователя.
- Очередь задач на той же БД даёт атомарность claim'ов и переживание рестартов (ADR-003).

Отрицательные/требующие внимания:

- SQLite — не сетевой сервер: многопоточность/многопроцессность требует аккуратных настроек (WAL, busy timeout), это учитывается в Task 04/08.
- Объём данных ограничен одним пользователем; масштабирование за пределы MVP потребует пересмотра.
- Бэкап БД должен учитывать согласованность с файлами аудио/артефактов (Task 18).

## Alternatives considered

- PostgreSQL: избыточен для MVP, требует отдельного процесса и обслуживания; отложен.
- «Только файлы» без БД: не даёт транзакционности, целостности связей и надёжной очереди задач.
- Redis/Celery/Kafka для очереди: см. ADR-003.
