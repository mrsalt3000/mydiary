# ADR-004: Провайдер-нейтральная OpenAI-совместимая LLM-абстракция

- Status: Accepted
- Date: 2026-09-09

## Context

Три LLM-задачи (нормализация, саммаризация, wellbeing) должны независимо использовать локальные или коммерческие модели; STT-задача — локальный провайдер (faster-whisper). Требуется переключать эндпоинт/модель **только конфигурацией**, не меняя код, и делать это безопасно: секреты — из окружения, внешние вызовы — только с явного согласия.

## Decision

Вводится провайдер-нейтральная абстракция LLM: протокол/интерфейс `LLMProvider` и реализация `OpenAICompatibleProvider` на HTTPX (Task 11), покрывающая как локальные OpenAI-совместимые эндпоинты, так и коммерческие. Нормализованные объекты запроса/ответа не зависят от реализации провайдера. Профиль задачи (из конфигурации Task 03) определяет провайдера и параметры. Захватывается происхождение (provenance): тип провайдера, модель, версия промпта, временные метки, статус, токены при наличии, хэш входа, класс ошибки. API-ключи не персистятся; содержимое дневника/промпты не логируются. Для STT действует аналогичный узкий интерфейс `TranscriptionProvider` (Task 09) с локальными реализациями.

## Consequences

Положительные:

- Один механизм для локальных и внешних моделей; переключение моделей/эндпоинтов по конфигурации (критерий Task 11).
- Единая точка политик: таймауты, повторы, безопасные ошибки, запрет секретов в логах/БД/UI.
- Тестируемость через mock/fake-провайдеры без реальных вызовов.

Отрицательные/требующие внимания:

- Поддерживаются только OpenAI-совместимые API; иные форматы требуют новых адаптеров (вне MVP).
- Внешние эндпоинты означают передачу данных наружу — управляется явным включением в конфигурации и раскрытием в UI/документации (см. `docs/privacy-and-safety.md`).

## Alternatives considered

- Прямые SDK каждого вендора: связывает код с вендором, усложняет локальные эндпоинты; отклонено.
- Единый «умный» клиент с автоматическим выбором: избыточен; выбран явный per-task профиль.
- Только локальные модели: не удовлетворяет требованию опциональных коммерческих моделей.
