# ADR-005: Первичные данные неизменяемы; производные артефакты версионируются и прослеживаются

- Status: Accepted
- Date: 2026-09-09

## Context

Дневник содержит личные записи и производные от них тексты (нормализация, саммари, wellbeing). Перезапись или потеря оригиналов недопустима: это единственный достоверный источник фактов. Повторные прогоны LLM дают разные результаты, поэтому производные результаты должны накапливаться, а не заменяться.

## Decision

Класс «источник» (исходные сообщения пользователя, аудиофайлы, сырые транскрипции, оригинальные еженедельные выгрузки) — **неизменяем**: ни один конвейер не модифицирует его; файлы не перезаписываются; записи не правятся. Класс «производные артефакты» (слои 2–4) — **версионируется** (`v1`, `v2`, …) и прослеживается до точного входа и прогона. Повторная выгрузка недели создаёт новую ревизию оригинала (`r1`, `r2`, …) только явным действием пользователя.

Трассируемость каждого производного артефакта обеспечивается: ID записей в БД, SHA-256 файлов, профилем задачи, идентификатором модели, версией промпта, временными метками и ID прогона обработки. Связи фиксируются внешними ключами (`weekly_exports` → `processing_runs` → `artifacts`).

## Consequences

Положительные:

- Гарантия сохранности фактов; сравнение версий; аудит того, что видел LLM.
- Повторные прогоны безопасны и предсказуемо именуются (номера/ревизии/версии без перезаписи).

Отрицательные/требующие внимания:

- Рост числа файлов при частых повторных прогонах — управляется политикой хранения/бэкапов (Task 18), без автоматического удаления источников.
- Согласованность «файл ↔ БД» и атомарность записи обязательны (Task 10/12); частичные артефакты запрещены.

## Alternatives considered

- Перезапись производных файлов при повторном прогоне: теряет историю и возможность сравнения; отклонено.
- Хранение производных только в БД без файлов: противоречит ADR-002 и удобству бэкапов/скачивания.
- Иммутабельность и для производных: избыточно, мешает полезным повторным прогонам.
