# Известные ограничения (начальные)

- Дата: 2026-09-09.
- Статус: зафиксировано на этапе подготовки (до Task 01); пересматривается после MVP (Task 19, раздел known-limitations).

## 1. Состояние реализации

- Репозиторий содержит только структуру и документацию. Приложение, БД, конвейеры и UI **не реализованы**; никаких заявлений о работающем продукте в документации нет.
- Технологические кандидаты (см. `architecture-brief.md`) не установлены и не проверены; точные версии валидируются в Task 01 и далее.

## 2. Сознательные исключения на этапе подготовки

- `.gitignore` не создан до Task 01 (скоуп задачи по `../tasklist.md`); до инициализации Git и Task 01 репозиторий не содержит пользовательских данных. Политика неприкосновенности `data/` зафиксирована документально (`../data/README.md`, `privacy-and-safety.md`, `AGENTS.md`).
- Git-репозиторий не инициализирован (не запрошено).
- Не созданы: `.env`/`.env.example`, конфиги, зависимости, код, миграции, БД, аудио, выгрузки, бэкапы.

## 3. Технические ограничения, ожидающие валидации

- Точные пакеты и версии Python-стека (FastAPI, SQLAlchemy 2, Alembic, HTTPX, Pydantic Settings, faster-whisper) — не зафиксированы (Task 01/03/09).
- Поведение SQLite под нагрузкой web + worker (WAL, busy timeout, конкурентный claim) — проверить в Task 04/08.
- Совместимость форматов аудио браузера с выбранным STT (MediaRecorder → конвертация/FFmpeg) — Task 07/09.
- GPU/CUDA в WSL 2 — опционально и зависит от окружения пользователя (Task 09/17).

## 4. Продуктовые ограничения MVP (осознанные)

- Нет полнотекстового поиска (FTS5) по истории.
- Нет тегов, трендов, месячных/квартальных саммари.
- Нет шифрования at rest и локальной аутентификации/PIN (оценка в Task 18 как опция/пост-MVP).
- Нет мультиустройственности, мобильных клиентов, многопользовательности.
- Нет RAG/векторного поиска, календаря, напоминаний, диаризации спикеров.
- Нет распределённой обработки (Redis/Celery/Kafka/Kubernetes).
- Wellbeing-функция сознательно недиагностическая и не является кризисной помощью (ADR-006).
- Поддерживаются только OpenAI-совместимые LLM-эндпоинты.

## 5. Риски, к которым вернуться после MVP

- Рост числа файлов при частых повторных прогонах (ревизии/версии) → политика хранения.
- Объём единственной SQLite-БД и очереди при многолетнем использовании.
- Согласованность бэкапа «БД + файлы» при активной записи.
- Точность STT на русском языке и качество нормализации на реальных данных (оценивается пользователем на синтетических/личных данных вне репозитория).
- Актуальность эскалационного контента wellbeing-сценария (поддерживается отдельно от кода).
- Поведение внешних LLM-провайдеров (изменения API, rate-limit) — обработка через безопасные сбои (Task 11).
