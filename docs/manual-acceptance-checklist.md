# Manual acceptance checklist — Local Diary MVP на WSL 2

Ручной сценарий приёмки MVP после Task 19. Предполагается окружение WSL 2 (Ubuntu), Python 3.12 (`~/.local/bin/python3.12`), `make`; подробности развёртывания — в `README.md` и `docs/wsl2-deployment-brief.md`.

Используйте **только синтетические записи** (личные данные в проверку не вносите).

## 0. Подготовка

- [x] `make install` выполнен без ошибок (создан `.venv/`).
- [x] `cp .env.example .env`; при необходимости задан `APP_TIMEZONE` (по умолчанию `Europe/Moscow`).
- [x] Скопирован и при необходимости отредактирован конфиг моделей: `cp configs/models.example.yaml configs/models.yaml` (для локального/внешнего LLM-эндпоинта). Если используется только UI без LLM-шагов — файл можно не создавать, страницы не падают.
- [x] Применены миграции: `make migrate` (создаст `data/db/diary.db`).
- [x] (Опционально) CPU-транскрипция: `.venv/bin/pip install -e ".[stt]"` (нужен также ffmpeg в системе для записи с микрофона/конвертации, если браузер пишет не-WAV).
- [x] Проверки кода (по желанию): `make test`, `make lint`, `make typecheck` — зелёные.

## Результат прогона приёмки (2026-09-19)

Приёмка проведена на **изолированном стенде**, а не на рабочем каталоге данных:
`APP_DATA_ROOT=/tmp/acceptance/data` (все подкаталоги redirected), отдельный `models.yaml`
(копия рабочего с `language: en` под синтетическую речь), web на порту 8010 и отдельный
воркер. Личные записи в проверке не участвовали: текст — синтетический, речь сгенерирована
локально фильтром `ffmpeg -f lavfi -i flite`.

Изоляция подтверждена измерением: в рабочем каталоге данных за окно приёмки (16:18-17:05 UTC)
не создано **ни одной** записи ни в одной таблице.

### Отклонения от методики

1. **Браузер не использован.** Проверки выполнены через API и серверно-рендеренный HTML.
   Для слоёв данных и состояний это эквивалентно (состояния отдаются сервером), но реальных
   кликов и работы JS на живом браузере не было — визуальная раскладка не проверена.
2. **Микрофон заменён загрузкой WAV** — раздел 3 это прямо допускает.
3. **Порт 8010 вместо 8000** — следствие изоляции стенда.
4. **Раздел 9 (Docker) не выполнялся.** `docker-compose.yml` монтирует `./data:/app/data`,
   то есть проверка затронула бы рабочие данные. Для безопасного прогона нужен отдельный
   override с синтетическим томом.

### Наблюдения

- Повторный запуск слоя с **тем же** входом дедуплицируется, пока предыдущий прогон в полёте;
  версия `v2` появляется, когда вход изменён (например, новая ревизия оригинала) или прогон
  завершён. Формулировку пункта в разделе 5 стоит уточнить.
- Внешний LLM-провайдер во время приёмки работал нестабильно: три прогона нормализации
  упёрлись в ~134-135 с и ушли в ретраи, после чего прошли за 7-19 с. Политика ретраев
  отработала, данные не пострадали (все файлы сверены по sha256).
- Бэкап выгружает БД через API SQLite, поэтому файл БД внутри архива не побайтово равен
  «живому» файлу с незавершённым WAL. Логическая эквивалентность проверена сравнением
  дампов всех 8 таблиц.
