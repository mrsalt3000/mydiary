## 2. Что запущено сейчас и как этим управлять

| Компонент | Как поднят | Как остановить |
|---|---|---|
| Веб :8000 | `scripts/run-local.sh web --host 127.0.0.1 --port 8000` | kill процесса `uvicorn diary.main` |
| Воркер | `scripts/run-local.sh worker` | kill процесса `diary.workers.runner` |
| Ollama :11434 | `setsid nohup ~/.local/bin/ollama serve` с `OLLAMA_KEEP_ALIVE=0`, `OLLAMA_MAX_LOADED_MODELS=2` | убить процесс `ollama serve` |

**Ловушки окружения (проверены на практике):**

1. **Запускать только через `scripts/run-local.sh`**, не через `make dev`: он экспортирует `.env` (иначе `*_API_KEY` не резолвятся — в проекте нет `load_dotenv`) и ставит cuBLAS-шим для GPU-Whisper.
2. **`scripts/serve-ollama.sh stop` не остановит сервер, поднятый вручную** — он отказывается работать без pid-файла. Поднимать/останавливать сервер лучше одним способом.
3. Профили фазы 2 требуют непустого **`OLLAMA_API_KEY`** в `.env` (значение Ollama игнорирует). Добавлен.
4. Сервер запущен **без `--reload`** — после правок Python его надо перезапускать; шаблоны и статика читаются с диска, поэтому при закэшированном HTML нужен **Ctrl+F5**.
5. `num_ctx` задаётся только в `Modelfile` тега, не в конфиге. `reasoning_effort: none` обязателен: иначе размышление съедает `max_tokens` и `content` приходит пустым.

## 3. Ждут решения пользователя

1. **`KEEP_ALIVE`:** сейчас `0` (VRAM свободна, но каждый вызов платит загрузку ~3.5–4.6 с). Возврат к `5m` ускоряет интерактивные слои, но открывает окно, в котором резидентный **CPU-тег недели обслуживает запросы к GPU-тегам** — замер: `cli coach` 108 с вместо 8.45 с.
2. **Пороги T10** (правка < 5 с, день < 15 с) калиброваны под GPU и на CPU-маршруте недостижимы; формулировка пользователя «до 3 минут» мягче. Менять пороги — только его решением.

## 4. Остаток работы, по убыванию ценности

1. **F1 (главное).** Инварианты «нет советов / домыслов / диагнозов» (`ADVICE_EVALUATION_LEXEMES`, `CAUSAL_CONNECTOR_LEXEMES` в `src/diary/domain/contracts/golden.py`) применяются **только в `eval/`**: ни оркестратор, ни слои, ни воркер их не используют. В продакшне эти пункты держатся **только на промпте**, поэтому пункты 4–5 чеклиста §7 красные. Доказательства: `щас → Сегодня` в 3 из 4 прогонов; причинные связки; подмена числа («два часа» вместо «1 час 20 минут»); инверсия смысла («позже планового срока» при входе «раньше плана»).
2. **Развести в харнессе счётчик латентности и счётчик инвариантов** (или прогревать модель): сейчас `eval/run.py` считает их одним числом, и в текущем рантайме порог 8/10 недостижим из-за холодной загрузки — красный гейт читается как нарушение содержания.
3. **Покрыть харнессом недельный профиль.** Проверено: `PROFILE_NAME_BY_CATEGORY` в `eval/run.py` мапит `week` на `diary_sum`, поэтому маршрутизация T13b и CPU-тег `diary-sum-cpu` регрессиями **не проверяются вообще**.
4. **Бюджеты.** Фактические размеры промптов: неделя — 3131 оценочных токенов, coach — 4029, день — 2124, STT — 1509; `LAYER_PROMPT_TOKENS_EST` помнит 1629/1968/1932/1509. С исправленной константой проверка бюджета для coach выходит за 8192. **У coach-слоя гейта бюджета нет вовсе** (в `coach/*.py` ни `NUM_CTX`, ни `estimate_tokens`).
5. **`no_new_facts` даёт ложные срабатывания** на «семь дней» и «первый день» — проверка строже, чем нужно.
6. **Мелочи T11:** таймаут выгрузки трактуется как «модели нет» вместо fail-closed; обработчики фазы 2 не транслируют `ModelsConfigError` в permanent; `--tz` без валидации даёт traceback; `request_transcription` отвечает 202 на удалённое аудио; `DELETE` даёт 500 при испорченном `storage_path`.
7. **Хвосты UI:** карточка аудиосообщения без строки `audio_files` рисует `id="transcription-None"` и кнопку «Расшифровать» (наследие T07/T16b); панель даёт N+1 запросов на рендер.
8. **Из макета сознательно не сделаны** (каждая потребует бэкенда, поэтому не нарисованы пустышками): «Хронология», «Настройки», поиск, поштучный экспорт, «Показать происхождение».

## 5. Факты о среде, которые дорого переоткрывать

- **Ollama в user space** (`~/.local`), `sudo` требует пароль; релизы — `.tar.zst`, бинарника `zstd` нет, распаковка через системный `/usr/bin/python3` (3.14, `tarfile`, `filter="data"`).
- **`reasoning` тратит `max_tokens`**; `/v1` **не наследует** `top_p` и `temperature` из тега; резидентно загруженный CPU-тег перехватывает запросы к GPU-тегам.
- **Whisper large-v3 на GPU** требует шима `libcublas.so.12` (`~/.local/lib/ct2-cuda`), иначе падает на инференсе.
- **Микрофон на хосте Windows отключён системно**, поэтому UI-проверки делаются настоящим Chrome на стороне Windows через CDP либо Chromium из `~/.cache/ms-playwright` в WSL, с флагами фейкового устройства.
- **Нормализация — перезапись без потерь** (выход ≈ вход), поэтому на локальном 4B её надо дробить мелко: `APP_NORMALIZE_CHUNK_ENTRIES=5`.

## 7. Процессные уроки этой сессии

1. **Заявленная агентами уборка временных файлов не выполняется** — три этапа подряд (T16a: три профиля браузера 15–22 МБ; T16b: 97 МБ стенда и дифф отрендеренной страницы чата; T16c: остатки перечислены, но не убраны). Нужен отдельный пункт приёмки «уборка проверена», иначе остаются кэши с текстом дневника.
2. **Пуш внутри составной команды не уходит** (дважды): `git push` надо вызывать отдельным вызовом и проверять `git status -sb`, иначе можно отчитаться «запушено» про локальный коммит.
3. **Шаблоны поиска процессов должны не совпадать с собственной командой** — `pkill -f '<текст>'` убивал мой же шелл (дважды). Писать `'diary[.]workers'`-подобные шаблоны.
4. **Провайдер срывает запуск субагентов** примерно в половине случаев; при двух отказах подряд надо либо повторить коротким брифом, либо проверять критичное самому и честно помечать, что независимой приёмки не было (так было с T13b, T16b).
5. **Отчёты агентов требуют проверки фактом**: за сессию найдены невыполненная уборка, заниженный объём стенда, изменение существующего теста под новую политику, ложное «недостижимо» в докстринге.
