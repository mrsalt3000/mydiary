# Skill: llm-pipelines

## Purpose

Правила LLM-функциональности: провайдерная абстракция, внешний opt-in, промпты, структурированный JSON-вывод с Pydantic-валидацией, происхождение (provenance), запрет данных дневника в логах. Охватывает фреймворк конвейеров и слои 2–4 (нормализация/саммари/wellbeing — см. также `wellbeing-safety`).

## Scope and boundaries

- Входит: `LLMProvider`/`OpenAICompatibleProvider` (HTTPX), профили задач, конвейеры производных артефактов, версии промптов, валидация ответов, provenance.
- Вне границ: локальная транскрипция (local-stt), недельная выгрузка оригинала (weekly-export), специфика wellbeing-ограничений (wellbeing-safety).

## Mandatory rules

- Интерфейс провайдера нормализован; переключение моделей/эндпоинтов — конфигурацией профиля, не кодом (ADR-004).
- Секреты — только по имени переменной окружения; ключи не персистятся и не логируются.
- Содержимое дневника, промпты с ним и ответы LLM не логируются (никакой уровень INFO/WARNING/ERROR).
- Внешние эндпоинты — только при явном `external: true` и раскрытии в UI/документации; автоматических вызовов нет.
- Промпты версионируются в `../prompts/<task>/v<N>.md`; версия фиксируется в метаданных прогона; промпты не содержат данных дневника.
- Структурированный вывод (JSON) валидируется Pydantic **до** записи файлов; невалидный вывод → failed processing run, без частичного артефакта.
- Финальные файлы рендерит бэкенд из валидированных данных, не «сырой» вывод LLM.
- Вход конвейера — по ID артефакта из БД (не glob'ы по ФС); источники не модифицируются; повторный прогон — новая версия `vM+1`.
- Provenance каждого прогона: тип провайдера, модель, версия промпта, время, статус, токены при наличии, хэш входа, класс ошибки.
- Ошибки сети/таймаута/аутентификации/rate-limit/формата — безопасные сбои, ретрабельные по политике (Task 08/11).
- Обработка длинных входов: нормализация — чанкинг с сохранением порядка; саммари — single-pass ниже порога, map-reduce выше (промежуточные выходы — метаданные/контролируемые temp-артефакты).

## Expected module locations

- `../src/diary/domain/llm/` — провайдеры и структурированные ответы; `../src/diary/domain/pipelines/` — оркестрация.
- `../prompts/{normalize,summarize,wellbeing}/v<N>.md`.
- Таблицы `processing_runs`, `artifacts`, `jobs` — в `../src/diary/db/`; тесты — `../tests/`.

## Quality and security checks

- Тесты на fake-провайдере: успех, malformed JSON, отсутствующая запись, чанкинг, rerun-версионирование, неизменность оригинала, отсутствие секретов/дневника в логах и ответах.
- Проверка, что слой 3 и 4 строятся только от нормализованного входа.
