# Skill: backend-fastapi

## Purpose

Правила построения HTTP-слоя FastAPI в этом проекте: тонкие роутеры, схемы, сервисы, маппинг ошибок, границы внедрения зависимостей. Обеспечивает соответствие архитектурным границам (`../docs/architecture-brief.md`, §4).

## Scope and boundaries

- Входит: роуты и схемы API, связывание роутер → сервис, безопасный рендер/адаптеры, обработка ошибок уровня HTTP, DI-границы.
- Вне границ: бизнес-логика (в domain-сервисах), доступ к БД (в `db/`), файловые/LLM-операции (в domain).

## Mandatory rules

- Роутер: HTTP-валидация → вызов сервиса → ответ; без бизнес-логики и прямых обращений к SQLAlchemy-сессиям из роутера.
- Pydantic-схемы для входа/выхода API; секреты и содержимое дневника в схемах/ответах/логах запрещены.
- Ошибки предметной области маппятся в HTTP-ответы понятным образом; внутренние детали/стектрейсы/сырые payload'ы провайдеров не раскрываются.
- Только localhost по умолчанию; загрузка файлов — серверная валидация и серверные пути.
- Тесты API — в `../tests/integration/` (или unit для схем).
- Версионирование/группировка роутов — по решению задачи (Task 05); изменения требуют плана.

## Expected module locations

- `../src/diary/api/` — роуты и схемы; `../src/diary/core/` — конфигурация/DI; сервисы — в `../src/diary/domain/*/`.
- Шаблоны/статику см. `frontend-htmx`.

## Quality and security checks

- Схемы валидируют пустые/слишком большие тела (Task 05), MIME/размер файлов (Task 07).
- Нет утечек секретов и личных данных в ответах и логах (проверка тестами).
- Тесты: валидация, статусы, персистентность, безопасный рендер, обработка ошибок.

## Typical validation commands (целевые, после Task 01)
