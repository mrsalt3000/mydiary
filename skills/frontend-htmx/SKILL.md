# Skill: frontend-htmx

## Purpose

Правила пользовательского интерфейса MVP: локальный server-rendered UI (Jinja2 + HTMX + минимальный JavaScript), безопасный рендер, базовая доступность, опрос статусов, UX подтверждений.

## Scope and boundaries

- Входит: базовые/страничные шаблоны, HTMX-фрагменты, формы и действия, отображение истории/выгрузок/артефактов/статусов, полировка доступности.
- Вне границ: роуты/схемы API (backend-fastapi), бизнес-логика и данные (domain), стилизация сверх минимальной — не цель MVP.

## Mandatory rules

- Server-rendered по умолчанию (Jinja2), HTMX для фрагментов и обновлений; тяжёлый клиентский JS не добавляется без плана.
- **Весь пользовательский текст экранируется** при рендере (защита от script injection); автоэкранирование включено; тесты на опасный ввод обязательны.
- Временные метки отображаются в `APP_TIMEZONE`.
- Асинхронные статусы (задачи/прогоны) — через опрос/обновление фрагментов; кнопки действий отображают queued/running/succeeded/failed.
- Деструктивные/создающие ревизии/версии действия и wellbeing-анализ требуют явного UI-подтверждения; перед внешним LLM — предупреждение о внешней обработке.
- Состояния: пустое, загрузка, ошибка валидации — понятные пользователю; ошибки без секретов и внутренних деталей.
- Доступность: семантический HTML, клавиатурная достижимость основных действий, разборчивый контраст (базовый уровень).

## Expected module locations

- `../src/diary/templates/` — шаблоны (base, чат, exports, processing, детали); `../src/diary/static/` — CSS и минимум JS.
- Роуты страниц — в `../src/diary/api/` (тонкие, см. backend-fastapi).

## Quality and security checks

- Тесты роутов/шаблонов: рендер истории, XSS-ввод не исполняется, статусы и подтверждения присутствуют, сообщения переживают refresh.
- Проверка отсутствия секретов/данных провайдеров в HTML.
